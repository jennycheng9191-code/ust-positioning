# 部位與波動追蹤（ust-positioning）

每週自動更新的靜態網站：把 CFTC 的部位報告變成一張可讀的圖——
誰在加倉、部位相對歷史有多極端、波動如何變化。

三個資產分頁共用同一套模組：

| 分頁 | 合約 | 分類法 |
|:--|:--|:--|
| **美債** | 2Y／5Y／10Y／Ultra 10Y／長債／超長債 | TFF ＋ Legacy |
| **原油** | NYMEX WTI | Disaggregated ＋ Legacy |
| **貴金屬** | COMEX 黃金、白銀 | Disaggregated ＋ Legacy |

（repo 名維持 `ust-positioning` 是為了不換網址與密碼記憶；站名已改為「部位與波動追蹤」。）

## 這個站在回答什麼

| 模組 | 問題 |
|:--|:--|
| M1 部位結構 | 現在誰站在哪一邊？各類交易人的多空規模與淨部位。 |
| M2 本週誰在加倉 | 這一週部位往哪裡動？是新增單邊部位，還是反向部位平倉。 |
| M3 部位極端度 | 現在的部位相對歷史有多極端？（Disagg／TFF 回溯至 2006、Legacy 至 1986） |
| M4 已實現波動 | 實際波動在放大還是收斂？美債看殖利率（bp），商品看價格報酬（%）。 |
| M5 配對 | *（貴金屬＝金銀比、原油＝Brent-WTI 價差）* 兩個市場之間的相對關係，與選定合約的價格疊圖。 |

各分頁最有訊號的一組：

- **美債**：TFF 的 **資產管理淨多 vs 槓桿基金淨空**，這組對峙是基差交易（basis trade）
  規模的體溫計；Legacy 則看 **非商業（投機）淨部位**，也就是新聞講「投機客淨空美債」的數字。
- **原油**：Disagg 的 **管理基金淨多**（投機資金）對 **生產商淨空**（產業避險壓力）。
- **貴金屬**：**管理基金**與**交換商**呈鏡像——交換商多是銀行替客戶做的對手方部位，
  兩者一起看才知道多空是誰對誰。

## 三套分類法

CFTC 對金融期貨與實體商品發的是不同的報告，所以分頁之間的分類法不通用：

| 分類法 | 適用 | 交易人類別 | 歷史起點 |
|:--|:--|:--|:--|
| **TFF** | 只有金融期貨 | 交易商／中介、資產管理機構、槓桿基金、其他可報告戶、非報告小戶 | 2006-06-13 |
| **Disaggregated** | 只有實體商品 | 生產商／貿易商、交換商、管理基金、其他可報告戶、非報告小戶 | 2006-06-13 |
| **Legacy** | 全部市場 | 非商業（投機）、商業（避險）、非報告小戶 | 合併版 1995-03-21／僅期貨 1986-01-15 |

角色上的對應關係（頁面上的線色也照這個對齊）：

| 角色 | TFF | Disagg | Legacy | 線色 |
|:--|:--|:--|:--|:--|
| 投機資金 | 槓桿基金 | 管理基金 | 非商業 | 紫 |
| 避險／實需 | 資產管理機構 | 生產商／貿易商 | 商業 | 金 |
| 中介 | 交易商 | 交換商 | —（併入商業） | 藍 |

**Legacy 用在商品與用在美債，可信度天差地遠。**
它的「商業」原意是持有現貨、用期貨避險的人——套在原油上就是煉油廠與貿易商，名副其實；
套在美債上卻變成大雜燴，資產管理機構與交易商都被歸進去（形式上它們持有現貨、算避險）。
同一天的 10 年期（2026-08-18）：Legacy 說投機客淨空 87.6 萬，TFF 說槓桿基金淨空 217 萬，
差兩倍半。CFTC 後來另出 TFF 就是為了解決這件事。頁面的分類法提示會依分頁換文案。

| 資料集 | Socrata ID |
|:--|:--|
| TFF 合併版 | `yw9f-hn96` |
| TFF 僅期貨 | `gpe5-46if` |
| **Disagg 合併版** | **`kh3c-gbw2`** |
| **Disagg 僅期貨** | **`72hh-3qpy`** |
| Legacy 合併版 | `jun7-fc8e` |
| Legacy 僅期貨 | `6dca-aqww` |

⚠️ **Disagg 的兩個代號與 TFF 的排列相反**：`kh3c-gbw2` 才是合併版
（WTI 在它底下未平倉 248.3 萬口，`72hh-3qpy` 只有 190.7 萬口，合併版必然大於僅期貨版）。
接反了兩份資料各自的恆等式仍成立，`validate.py` 抓不出來，只會看到「選擇權未平倉量是負的」。
`test_transform.py` 有一則測試把這兩個代號釘死。

CFTC 資料集本身有幾個既有的欄位拼字錯誤，必須照抄不可「順手修正」：
`swap__positions_short_all` 與 `swap__positions_spread_all` 是**雙底線**（多方欄只有一個）、
Legacy 的 `noncomm_positions_spread` 少一個 r。改成看起來正確的名字會抓到一整排 `None`，
而恆等式檢查因為分母也跟著少而驗不出來。同樣有測試釘住。

## 三種口徑

每套分類法各有合併版與僅期貨版兩個資料集，欄位定義一致，相減就得到第三種：

| 口徑 | 內容 |
|:--|:--|
| 期貨＋選擇權 | CFTC 合併版。選擇權部位以 delta 加權換算成期貨當量後併入 |
| 僅期貨 | CFTC 僅期貨版 |
| **僅選擇權** | **合併版 − 僅期貨版，本站計算**。CFTC 沒有直接發布這份 |

2026-08-25 的 WTI：合併版未平倉 248.3 萬口，其中選擇權 57.6 萬口（23.2%）。
美債 10 年期同期的選擇權佔比則是 11.6%——商品的選擇權相對更重。

**歷史起點不一定一致**：Legacy 的僅期貨版從 1986 年就有，合併版要到 1995 年
（CFTC 那年才開始發含選擇權的版本）。所以相減時只取兩邊都有的報告日。

極端度按「分頁 × 分類法 × 口徑」各自獨立計算：選擇權部位的歷史分布跟期貨完全不同，
Legacy 的樣本又比 TFF／Disagg 多十幾年，混用會得到無意義的百分位。頁面上會標出樣本週數。

## 波動度的單位不同，不可並排

美債頁算的是**殖利率日變動**的滾動標準差，年化後單位 **bp／年**；
商品頁算的是**價格日對數報酬**，年化後單位 **%／年**。
債券交易員講波動講的是走了幾個 bp，商品講的是漲跌百分之幾——兩者不是同一件事。

WTI 在 2020-04-20 出現過負結算價（`DCOILWTICO` 為 −36.98），取對數會直接把管線炸掉。
`realised_vol_price()` 會跳過非正價格與其相鄰的兩筆報酬，並有測試釘住。

## M5 配對模組（貴金屬與原油頁）

兩條價格序列合成一條，與選定合約的價格疊在**雙 Y 軸**上。左軸配對值、右軸價格。
比值 ~65 與金價 ~4,563 差兩個數量級，共用一根軸會把比值壓成一條直線；
代價是**不能讀高低、只能讀方向關係**，說明文字裡有寫明。

| 分頁 | 指標 | 算法 | 目前值 | 2006 起全樣本 |
|:--|:--|:--|--:|:--|
| 貴金屬 | 金銀比 | `gold ÷ silver` | 64.94 | 31.53 – 123.49 |
| 原油 | Brent-WTI 價差 | `brent − wti` | +4.34 美元／桶 | −22.18 – +54.34 |

**比值與價差不是同一種東西，程式裡刻意分開處理：**

| | 比值（ratio） | 價差（spread） |
|:--|:--|:--|
| 算式方向 | `gold ÷ silver` | `brent − wti`，**Brent 溢價為正**（市場報價慣例） |
| 值域 | 恆為正 | 有正負，**零是有意義的分界** |
| 零線 | 不畫（浪費縱軸） | **一定畫**，且縱軸強制含 0 |
| 非正值 | 分母 ≤ 0 就跳過（除法會爆） | **不過濾**——Brent−WTI 在 2020-04-20 的減數是負的（WTI −36.98，真實成交價），正好踩中比值那條規則，但當天價差 +54.34 是那場事件的核心事實，濾掉等於竄改歷史 |

`test_pair_spec_points_at_real_series` 會檢查「價差才畫零線」這條規則沒被寫反。

| 項目 | 做法 |
|:--|:--|
| 序列計算 | 兩條序列**內連接**，只取都有報價的日期。休市日各家不同——2006 年起白銀有 40 天黃金沒報價；WTI 與 Brent 兩邊各有缺口（Brent 獨有 87 天、WTI 獨有 46 天，共同日 5,135 天）。用前值補會憑空造出「當天的變動」，而這兩張圖的用途正是看它怎麼動 |
| 圖的區間 | 近三年，與 M3 部位軌跡、M4 波動度同一個時間尺度，整頁好對照 |
| 百分位 | 用 2006 年起的**全樣本**。兩個都是長週期指標，只看三年會把極端讀成常態。百分位用排序名次算，所以 2020 那種離群值不會扭曲刻度，留著才是對的 |
| 兩線起訖 | 圖上裁到共同區間，否則其中一條會多出一截沒有對照的尾巴，讀起來像另一個數列缺值 |
| overlay | 決定選到哪一檔合約時右軸疊哪條價格。貴金屬頁金銀各疊自己的價；原油頁只有 WTI 一檔，固定疊 WTI |

**兩個指標怎麼讀**

- **金銀比走高＝白銀相對弱**。白銀有一半以上的需求來自工業，景氣轉弱或避險情緒升高時
  它跌得比黃金兇；比值走低多半出現在再通膨與工業需求回溫的階段。
- **Brent-WTI 價差走闊（Brent 溢價擴大）**多半反映美國本土供給過剩或外輸瓶頸
  （管線、出口能力）；收斂甚至翻負，則代表美國原油更容易走向國際市場。
  2006 年以來仍有 950 個交易日是負的，所以零線不是裝飾。

歷史檔按分頁分開（原本是單一 `cot_history.csv`）：商品的 Legacy 僅期貨版回溯到 1986 年，
合起來一個檔會逼近 30 MB，每週改寫一次對 git 不友善。拆開之後改一頁只動一個檔。

### CSV 的換行一定要是 LF

`build.py` 的 `csv.writer` 有寫死 `lineterminator="\n"`，`.gitattributes` 也標了
`*.csv text eol=lf`。**兩道都不能拿掉。**

Python 的 `csv.writer` 預設用 `\r\n` 結尾——**連 Linux 也是**。而本機 git 開了
`core.autocrlf=true`，commit 時會把 CRLF 正規化成 LF；Actions 的 runner 沒開這個設定，
就照 CRLF 存。兩邊存進 git 的 blob 因此不同，只要本機建置一次再讓排程跑一次，
這三個檔（合計 22 MB）就整份改寫一遍。

2026-08-29 實測過一次：Actions 的一個 `資料更新` commit 是 **253,383 行全刪全增**，
而內容一個字都沒變。每週來一次，一年就把倉庫撐掉好幾 GB。

各檔為長格式，一列一個「報告日 × 分類法 × 口徑 × 合約 × 交易人類別」。
要單獨看選擇權篩 `basis=options`；要對照新聞的「投機客淨部位」篩
`scheme=legacy & category=noncomm`。

## 排程

`.github/workflows/update.yml` 一週跑三次：

| 時間（台北） | 用意 |
|:--|:--|
| 週六 09:17 | 主場。CFTC 週五 15:30 ET 發布後幾小時。 |
| 週六 21:17 | 對 GitHub 排程延遲避險。 |
| 週二 09:17 | 遇美國假日 CFTC 順延至週一發布時，由這次補回。 |

刻意避開整點與 UTC 00:00（同架構的美國總經手冊實測穩定遲到 10 小時以上）。

三個分頁的部位資料來自同一批 COT 報告、同一個發布時點，所以共用一組排程，
不需要像澳洲手冊那樣另立時區節奏。

### 排程沒起來的時候

網站狀態列有一個「手動更新 ↗」按鈕，連到這個 repo 的 update workflow 頁面，
在該頁右上角按 **Run workflow** 就會重跑一次（等同排程做的事）。

按鈕旁邊的狀態方塊分三段，判定基準是「**下一期該發布了沒**」而不是「這份資料幾天前的」——
COT 報週二部位、週五才發，正常情況下站上永遠是三到十天前的數字，
看資料年齡分不出「本來就這樣」和「更新掛了」：

| 狀態 | 條件 | 顯示 |
|:--|:--|:--|
| 正常 | 還沒到下期預定發布日 | 下期預定 YYYY-MM-DD |
| 等待中 | 已過發布日 0–4 天 | 新一期應已發布，等待更新（黃框） |
| 逾期 | 已過發布日 4 天以上 | ⚠ 已逾預定發布日 N 天仍未更新（黃框＋按鈕高亮） |

寬限四天是因為 CFTC 遇美國假日會把發布順延到下週一（+3 天），加上排程本身可能晚幾小時。

另外排程失敗時 workflow 會自動開一張 GitHub issue，GitHub 會寄信通知，
所以多數情況不需要主動盯著網站看。

按鈕連去哪由 `data/latest.json` 的 `meta.repo` 決定（Actions 上取 `GITHUB_REPOSITORY`，
本機取 `build.py` 的 `REPO` 常數），前端不寫死部署位置。

## 加一個新分頁要改哪裡

前端完全由 `latest.json` 驅動，`app.js` 裡沒有任何 `if (asset === 'oil')`。
加分頁只要動 Python：

1. `cftc.py` 的 `ASSETS` 加一筆（合約、代碼、要用哪幾套分類法、預設合約）。
2. 若是新的分類法，`SCHEMES` 加資料集代號與欄位對應表；`SCHEME_NOTES` 加解讀提醒。
3. `prices.py` 的 `SERIES` 加價格序列（或美債那種殖利率就走 `fred.py`）。
4. `build.py` 的 `VOL_SPEC`／`VOL_PLOT`／`VOL_COLORS`／`SOURCE_NOTES` 各加一筆。
5. `validate.py` 的 `floors` 加歷史檔列數下限。
6. 若這一頁有值得看的配對指標，`build.py` 的 `PAIR_SPEC` 加一筆
   （`op` 選 `ratio` 或 `spread`），M5 就會自己出現；沒加就整段不顯示（連標題都不留）。

`test_transform.py` 的 `test_assets_are_self_consistent` 會檢查上述幾張表有沒有漏——
那類錯誤原本要跑完整條抓取管線（數分鐘）才會浮現。

## 已知限制

- **看不到價格位置。** COT 講的是「誰持有多少」，不是「押在哪個價位」。
  要做履約價層級的分析，需要 CME 的正式授權（DataMine 或已取得轉授權的資料商）。
- **週頻且延遲三天。** 報的是週二收盤部位，週五才公布。市場劇烈波動時，
  看到的是三天前的樣子。頁面最上方固定標示部位日期。
- **M4 是已實現波動，不是隱含波動。** 它講市場已經走過什麼，不是市場預期什麼。
- **Brent 只有價格沒有部位**，理由見上面的合約表。
- **貴金屬的價格來源有授權風險**，見「資料來源」一節。
