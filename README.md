# 美債部位與波動追蹤（ust-positioning）

每週自動更新的靜態網站：把 CFTC 的美債部位報告變成一張可讀的圖——
六檔美債合約、兩套交易人分類法、三種口徑（期貨／選擇權／合併），
誰在加倉、部位多極端、殖利率波動如何變化。

## 這個站在回答什麼

| 模組 | 問題 |
|:--|:--|
| M1 部位結構 | 現在誰站在哪一邊？各類交易人的多空規模與淨部位。 |
| M2 本週誰在加倉 | 這一週部位往哪裡動？是新增單邊部位，還是反向部位平倉。 |
| M3 部位極端度 | 現在的部位相對歷史有多極端？（TFF 回溯至 2006、Legacy 至 1986） |
| M4 已實現波動 | 2Y／10Y／30Y 殖利率的實際波動在放大還是收斂？ |

TFF 分類下最有訊號的一組是 **資產管理淨多 vs 槓桿基金淨空**，
這組對峙是基差交易（basis trade）規模的體溫計；
Legacy 分類下則看 **非商業（投機）淨部位**，也就是新聞講「投機客淨空美債」的那個數字。

## 兩套分類法

對美債而言 CFTC 只發兩套分類（Disaggregated 那份是實體商品用的，不含美債）：

| 分類法 | 交易人類別 | 10 年期歷史起點 |
|:--|:--|:--|
| **TFF**（預設） | 交易商／中介、資產管理機構、槓桿基金、其他可報告戶、非報告小戶 | 2006-06-13 |
| **Legacy** | 非商業（投機）、商業（避險）、非報告小戶 | 合併版 1995-03-21／僅期貨 1986-01-15 |

**兩者不可互相取代，也不該混用。** 同一天的 10 年期（2026-08-18）：
Legacy 說投機客淨空 87.6 萬，TFF 說槓桿基金淨空 217 萬——差兩倍半。
原因是 Legacy 的「商業」對金融期貨是個大雜燴，資產管理機構與交易商都被歸進去
（形式上它們持有現貨、算避險）。CFTC 後來另出 TFF 就是為了解決這件事。

各有各的用處：Legacy 歷史長 11 年、且是新聞引用「投機客淨部位」時講的那個；
TFF 分得細，看得到基差交易的對峙。

| 資料集 | Socrata ID |
|:--|:--|
| TFF 合併版 | `yw9f-hn96` |
| TFF 僅期貨 | `gpe5-46if` |
| Legacy 合併版 | `jun7-fc8e` |
| Legacy 僅期貨 | `6dca-aqww` |

## 三種口徑

每套分類法各有合併版與僅期貨版兩個資料集，欄位定義一致，相減就得到第三種：

| 口徑 | 內容 |
|:--|:--|
| 期貨＋選擇權 | CFTC 合併版。選擇權部位以 delta 加權換算成期貨當量後併入 |
| 僅期貨 | CFTC 僅期貨版 |
| **僅選擇權** | **合併版 − 僅期貨版，本站計算**。CFTC 沒有直接發布這份 |

2026-08-18 的 10 年期：合併版未平倉 669.5 萬口，其中選擇權 109.8 萬口（16.4%）。
值得注意的是選擇權撐大的主要是**總量**而非淨方向——同一天資產管理的淨部位，
合併版與僅期貨版只差 1,611 口，因為選擇權多空的 delta 大致互抵。

**歷史起點不一定一致**：Legacy 的僅期貨版從 1986 年就有，合併版要到 1995 年
（CFTC 那年才開始發含選擇權的版本）。所以相減時只取兩邊都有的報告日，
Legacy 的選擇權序列自 1995 起。

極端度按「分類法 × 口徑」各自獨立計算：選擇權部位的歷史分布跟期貨完全不同，
Legacy 的樣本又比 TFF 多 11 年，混用會得到無意義的百分位。頁面上會標出樣本週數。

CFTC 與 FRED 皆為美國聯邦政府公開資料，依 17 U.S.C. §105 不受著作權保護，
可自由使用與再散布。

> **本專案原本要做的是 CME 履約價層級的選擇權未平倉分析。**
> 技術上完全可行，但 CME Data Terms of Use 明文禁止以腳本系統性擷取其資料建立資料庫、
> 禁止再散布、也禁止 AI 相關用途，加密碼閘或設 private repo 都無法解決——
> 被禁的是「抓取建庫」這個動作本身。完整稽核見 AI 分身資料夾的
> `100_Todo/projects/2026-08-22_美債選擇權_資料源稽核.md`。

## 目錄

```
scripts/
  common.py    路徑、HTTP、UTF-8 輸出
  cftc.py      COT 抓取（含 Socrata 分頁）、兩套分類法的欄位對應表、口徑相減
  fred.py      殖利率抓取
  derive.py    淨部位、週變化、極端度、已實現波動
  build.py     主流程，產出 data/
  validate.py  產出檢查（過期門檻、恆等式、零和、選擇權範圍、列數）
  reconcile.py 對 CFTC 原始報告的外部對帳（合併版與僅期貨版）
  test_transform.py  回歸測試（不連網）
data/
  latest.json       網頁吃的那份
  cot_history.csv   完整週歷史，最早 1986 起，兩分類法 × 三口徑 × 六檔，約 159,000 列
                    （scheme 欄 tff／legacy，basis 欄 combined／futonly／options。
                     要單獨看選擇權篩 basis=options；要對照新聞的「投機客淨部位」
                     篩 scheme=legacy & category=noncomm）
docs/verification.md  對帳紀錄
```

## 本機執行

```bash
pip install -r requirements.txt
python scripts/test_transform.py   # 回歸測試
python scripts/build.py            # 抓取並產出
python scripts/validate.py         # 檢查
python -m http.server 8765         # 開 http://127.0.0.1:8765/
```

## 密碼

```bash
python scripts/set_password.py     # 在本機設定，只把 PBKDF2 雜湊寫進 assets/gate.js
```

這是**前端軟鎖**，不是存取控制。repo 是 public，`data/latest.json` 與
`data/cot_history.csv` 都能直接用網址開啟繞過閘門，原始碼在 GitHub 上也看得到。
它擋的是「隨手點進網址的人」與搜尋引擎收錄，不是有心人。

附帶一提，本站的資料本來就是美國聯邦政府的公開報告，任何人都能自己去 CFTC 下載——
所以這道門擋的是這個網頁介面，不是資料本身的機密性。要真正鎖住得改用
伺服器端驗證（Cloudflare Access 等）並把 repo 轉 private（Pages 免費方案不支援）。

`build.py` 是冪等的：資料沒變時產出的檔案位元組完全相同，所以排程不會累積空 commit。

## 排程

`.github/workflows/update.yml` 一週跑三次：

| 時間（台北） | 用意 |
|:--|:--|
| 週六 09:17 | 主場。CFTC 週五 15:30 ET 發布後幾小時。 |
| 週六 21:17 | 對 GitHub 排程延遲避險。 |
| 週二 09:17 | 遇美國假日 CFTC 順延至週一發布時，由這次補回。 |

刻意避開整點與 UTC 00:00（同架構的美國總經手冊實測穩定遲到 10 小時以上）。

## 已知限制

- **看不到價格位置。** COT 講的是「誰持有多少」，不是「押在哪個殖利率」。
  要做履約價層級的分析，需要 CME 的正式授權（DataMine 或已取得轉授權的資料商）。
- **週頻且延遲三天。** 報的是週二收盤部位，週五才公布。市場劇烈波動時，
  看到的是三天前的樣子。頁面最上方固定標示部位日期。
- **M4 是已實現波動，不是隱含波動。** 它講市場已經走過什麼，不是市場預期什麼。
